# K 近邻（K-Nearest Neighbors）原理

> 对应代码：`include/mini_mlmath/ml/knn.h`（完整实现）
> 配套测试：`tests/knn_test.cpp`
> 前置阅读：[感知机原理](perceptron.md)、[线性回归](linear_regression.md)

KNN 可能是整个机器学习里**数学最少、直觉最强**的算法：**要预测一个新样本，就看它在特征空间里离谁最近，让最近的 k 个训练样本投票决定它的类别。** 它没有一个「学出来的模型」——fit 只是把数据原样记下来，真正的工作全在 predict 时做。这种流派叫**懒学习（lazy learning）/ 基于实例的学习（instance-based learning）**，和感知机、线性回归那种「训练时解出一个 w」的**勤学习（eager learning）**正好是两个极端。

KNN 的「模型」就是训练数据本身。因此它逼你面对两个其它算法不需要纠结的问题，这也是本库把 KNN 设计成**两个扩展点**的原因：

1. **Metric**：怎么度量「两个样本有多近」？距离定义直接决定分类结果。
2. **Search strategy**：训练样本成千上万时，怎么**不扫描全量**也能快速找出最近邻？这就是 KDTree / BallTree 这类空间索引的用武之地。

本文件围绕这两件事展开（并和 `knn.h` 的代码一一对应），顺带讲 k 怎么选、投票权重怎么做。

## 1. 算法流程：三步走

```
fit(X, y)                          // 懒学习：只存数据，O(1) 逻辑
   记住 X（n 行样本）和 y（n 个标签）

predict(q)                        // 查询点 q，做三件事
  1. 算距离      d_i = metric(q, x_i)，i = 1..n
  2. 挑最近 k 个  取最小的 k 个（它们的下标集合记 N_k(q)）
  3. 多数投票    ŷ = N_k(q) 里出现次数最多的标签
```

第 1、2 步外包给「搜索策略」（本库的 `BruteForce` / `KDTreeSearch`），第 3 步是 KNN 自己的「投票」。所谓两个扩展点，就是把这两件最容易变的事从算法里拆出去——**换 metric 只改一个模板实参，换搜索策略也只改一个模板实参**（详见 §6 代码对应）。

## 2. 为什么它是「零训练」算法

对比本库三个模型，一眼看出差异：

| | 感知机 / 线性回归 | KNN |
|---|---|---|
| fit 干什么 | 迭代/解方程，产出 w、b | 原样存下 X、y |
| 训练耗时 | O(轮数 × n × d) | O(1)（就是拷贝）|
| 模型参数 | 一个权重向量 | **没有**——训练数据即模型 |
| predict 耗时 | O(d)（一个点积）| O(n×d + 排序)（要扫全部样本）|
| 学不会时 | 权重不收敛 / R² 难看 | 永远是「复制训练数据」，不会崩 |

这就是「懒 vs 勤」的本质交易：**训练省下的时间，predict 时连本带利还回去**。KNN 在训练上作弊，所以 predict 慢、还要存下全部数据。想提速，就得靠 §4 的空间索引把 predict 从 O(n) 压下去——**注意：索引仍然要预计算（build），所以别再说 KNN「零成本」——只是把成本从 fit 挪到了索引构建**（本库叫 `build`，见 §4.5）。

## 3. Metric：怎么定义「近」？

### 3.1 距离得满足三条公理

一个函数 d(a, b) 能当「距离」用，数学家要求它满足（在特征空间上）：

```
① 非负性    d(a, b) ≥ 0，且 d(a, b) = 0 ⟺ a = b
② 对称性    d(a, b) = d(b, a)
③ 三角不等式 d(a, c) ≤ d(a, b) + d(b, c)      ← 抄近路不超两边之和
```

三条都满足的叫**度量（metric）**，可以直接喂给 KNN。第③条最重要也最常被违反——「余弦相似度」就不是度量（见 3.4），直接拿它当 KNN 的距离要小心。

### 3.2 Lp 范数家族：L1 / L2 / L∞

先看一个统一公式——**闵可夫斯基距离（Minkowski）**，参数 p 取不同值就得到一族最常用的距离：

```
d_p(a, b) = ( Σ_i |a_i - b_i|^p )^(1/p)

p = 1   曼哈顿距离（L1）      Σ_i |a_i - b_i|
p = 2   欧氏距离（L2，默认）   sqrt( Σ_i (a_i - b_i)² )
p → ∞   切比雪夫距离（L∞）    max_i |a_i - b_i|
```

三种几何直觉（d=2 时，「到原点距离 = 1」的点集）：

```
L1 曼哈顿（菱形）           L2 欧氏（圆）            L∞ 切比雪夫（正方形）
     │\                           ╭─╮                     ╭───╮
     │  \                      ╭──╯   ╰──╮                 │   │
   ──┼──────                  │    ●    │               ───│ ● │───
     │  /                      ╰──╮   ╭──╯                 │   │
     │/                           ╰─╯                     ╰───╯
```

- **L2（欧氏）**：两点间直线距离。最直观、默认选它。平方项让**大偏差被放大**——一个维差 10 的贡献是差 1 的 100 倍，对异常值敏感。
- **L1（曼哈顿）**：只能「沿着坐标轴走」的路程。对每个维的偏差**线性**计费，不如 L2 那么被离群点绑架。特征维度较高、噪声较多时常比 L2 更稳（也常用在 Lasso 正则里）。
- **L∞（切比雪夫）**：只看**偏差最大的那一维**，其余维全部忽略。棋盘上王走一步最多动一格，从一个格子到另一个要几步，就是切比雪夫距离。适合「只要有一个维超出容忍范围就算远」的场景。

sklearn 的 `metric='minkowski'` + `p` 参数就是这三个的母版：`p=1` L1、`p=2` L2、`p→∞` L∞。

### 3.3 常见的非 Lp metric

**余弦相似度 / 余弦距离**（文本、embedding、向量检索的最爱）：

```
cos(a, b) = a·b / (|a|·|b|)         只看方向，不看长度
cosine_distance(a, b) = 1 - cos(a, b)   取值 [0, 2]，越小越近
```

几何意义：`{1,0}` 和 `{5,0}` 长度差 5 倍，但方向相同、余弦相似度 = 1。这对文档长度不一的 NLP 场景是**优点**（库的 `vector.h` 就实现了 `cosine_similarity`）。但当 KNN 的距离用时注意两点：① 余弦**不满足三角不等式**，严格说不是 metric（一般叫「半度量」/相似度）；② 它天然忽略向量的长度信息，若长度本身有意义（如某些数值特征），用余弦会丢掉它。工程上还有个常见变体**角距离** `arccos(cos(a,b))`，它满足三角不等式，可当 metric 用。

**汉明距离**（Hamming，分类/二进制特征）：

```
hamming(a, b) = 有多少个位置 a_i ≠ b_i
```

不比较数值大小，只数「不一样的位置」。典型用在 one-hot 编码、二进制指纹、纠错码上——`{猫,狗}` 和 `{猫,猪}` 的距离是 1（只有第 2 维不同）。

**杰卡德距离**（Jaccard，集合相似度）：

```
jaccard(A, B) = |A ∩ B| / |A ∪ B|     交并比
jaccard_distance = 1 - jaccard
```

看「两个集合的重合程度」，常用于稀疏的 0/1 特征（推荐系统、基因数据）。

**马氏距离**（Mahalanobis，带协方差统计）：

```
d(a, b) = sqrt( (a-b)ᵀ Σ⁻¹ (a-b) )       Σ = 特征协方差矩阵
```

普通欧氏假设**每个维同等重要、互不相关**；马氏距离用协方差 Σ 给每个维「加权」，把特征的尺度差异和相关性能都考虑进去。代价是要先估 Σ、且不能直接套 §4 的空间索引（每个查询点要变换一次）。理解它的直觉：**在数据「拥挤/拉长」的方向上，同样欧氏距离其实更近**。

### 3.4 怎么选 metric——经验法则

| 数据长什么样 | 常用 metric |
|---|---|
| 连续数值、各维量纲相近 | L2 欧氏（默认）|
| 连续数值、有噪声/离群点 | L1 曼哈顿 |
| 文本、embedding、向量检索 | 余弦（相似度/距离）|
| 二进制 / one-hot 特征 | 汉明 / 杰卡德 |
| 只需关心最大偏差 | L∞ 切比雪夫 |

⚠️ **选 metric 之前，先做特征缩放（标准化）**。这是 KNN 最容易翻车的地方：欧氏距离里，一个量纲为「万元」的特征（差值 ~10000）会**淹没**所有量纲为「个」的特征（差值 ~1）——相当于只看那一维。所以 KNN 实战前几乎必做 `z-score`（减均值除标准差）或 `min-max` 归一化，把每维压到相近尺度（库里的 `feature_selection/variance_threshold.h` 是删特征，不是缩放；标准化要自己写或加个 scaler）。KNN 不缩放 = 距离被量纲绑架，这是它和线性模型最大的不同。

**高维诅咒（curse of dimensionality）**：维数 d 升高后，所有点之间的欧氏距离会**趋于相等**——最近邻和最远邻几乎一样远，「离谁近」就失去区分度（直觉：维度越高，超立方体里「每个点都像在角落」）。经验上 d > 20~50 时 KNN 效果显著退化，这也是 §4 里 KDTree 在高维失效的同一根源。缓解思路：先降维/特征选择，或换对高维更稳的距离/模型。

## 4. Search strategy：怎么快速找 k 个最近邻居？

有了 metric，剩一个工程问题：预测时要把 q 和**每一个**训练样本算距离再挑最小 k 个吗？n 是百万量级、预测又频繁时这不可接受。于是诞生了「邻居索引」这一类数据结构：**预先（build）把数据组织成便于剪枝的结构，查询时只访问一小部分就能确定 k 近邻**。

### 4.1 BruteForce（线性扫描，本库默认）

```
build(q 无关)：存下 X，O(n)
query(q)：
  for i in 1..n:  d_i = metric(q, x_i)      O(n × d)
  挑最小的 k 个                               O(n·log k)（partial_sort）
  总复杂度：O(n·d + n·log k)，内存 O(nd)
```

不建任何索引，逐个算——**但正确性 100%，且实现最少**。n 小（几百上千）时它就是最优解，因为空间索引的 build 开销和缓存不友好访问反而更慢。sklearn 里 `algorithm='brute'` 就是这个。

### 4.2 KDTree：沿坐标轴切出来的二分树

**思路**：用一棵二叉树把空间递归对半切。每层选**方差最大（点最分散）的一个维**，取该维的**中位数**做分裂点，比它小的点进左子树、大的进右子树，递归到每片只剩少量点。这样每个树节点天然对应特征空间里的一块**轴对齐区域（bounding box）**。

```
建树（build，O(n·log n)）：
  KDNode(点集 S):
    选方差最大的维 j
    mid = S 按第 j 维排序后的中位数点
    node.axis = j；node.point = mid
    node.left  = KDNode({p∈S : p[j] < mid[j]})
    node.right = KDNode({p∈S : p[j] > mid[j]})

查询（query，平均 O(log n)）：
  递归下钻：查 q 在分裂点哪一侧就往哪走，顺路记住经过的叶子
  回溯时用「q 到另一侧子树边界盒的最短距离」剪枝：
     若 边界盒最短距离 > 当前已找到的第 k 近距离 → 整棵子树不可能有更近的，整块跳过
```

**为什么能跳过？** 靠的是「当前最远邻居距离」这个阈值（search radius）不断收缩。只要某子树的包围盒离 q 比阈值还远，盒子里任何点都不可能进前 k，直接放弃。数据分布越「聚集」（低维点云），下钻越深、剪枝越狠，查询越接近 O(log n)；反之退化。

**局限**（两条都要记住）：
- **高维失效**：维数升高后，包围盒离 q 的距离普遍变小、剪枝判断几乎总是不成立，查询退化回 O(n)（和高维诅咒同源）。经验阈值 d ≲ 20 才值得用。
- **强依赖坐标轴**：盒是轴对齐的。如果数据是倾斜的长条（比如沿 45° 线分布），轴对齐的盒会包进大量空区域，剪枝效率大打折扣。

### 4.3 BallTree：用超球包节点，补 KDTree 的短板

**区别就一个字：用「球」代替「盒」。** 每个节点不是一个轴对齐的盒，而是一个**最小包围超球（ball）**——球心和半径。代价是建树更贵（要找质心/半径），但换来两个好处：

- **包围更紧**：球没有「轴对齐」的假设，倾斜的长条数据也能包得很紧，剪枝更狠；
- **metric 无关**：KDTree 的「到盒子的距离」对非欧氏 metric 很难算；BallTree 只需要「到球心的距离 - 半径」这一条下界，**任何满足三角不等式的 metric 都能剪枝**——所以 sklearn 里遇到余弦等 metric 时 `kd_tree` 会静默回退到 `ball_tree`。

查询剪枝和 KDTree 一个套路，只是把「到盒的距离」换成「到球的距离」：

```
if  dist(q, node.center) - node.radius > 当前第 k 近距离:
    整棵子树跳过
```

### 4.4 怎么选——sklearn 的 algorithm='auto'

| 条件 | 该用谁 |
|---|---|
| n 小（< ~30，sklearn 经验值）| **BruteForce**（索引开销反而亏）|
| d 低（≲ 20）且用欧氏 | **KDTree**（球不球差距不大，KD 简单）|
| d 中低、metric 非欧氏 | **BallTree**（KD 不支持/退化）|
| d 高（> ~20）| **回退 BruteForce**（索引全部失效）|

sklearn 的 `algorithm='auto'` 就是自动套这条规则：**样本太少直接暴力；否则按 metric 能不能喂 KDTree、维数高不高，在 kd_tree / ball_tree 之间挑，维数太高退回 brute**。真实工程里别死记，先跑 brute 当基准、再试 KDTree/BallTree 比速度即可——**剪枝索引只是加速，不影响分类结果**（同样的 metric + k，三种策略输出必须一致，本库测试就是这么验证的）。

### 4.5 本库的现状与策略接口

`knn.h` 把搜索策略抽成一个「邻居索引」概念，任何策略类只需实现四个方法，KNN 就能用：

```cpp
template <typename T, typename Metric>
class SomeSearch {
public:
    void build(const Matrix<T>& X);                     // 建索引（BruteForce 只拷贝）
    std::vector<NeighborHit<T>> query(const T* q, std::size_t k) const; // 返回最近 k 个
    std::size_t sample_count() const;                   // 训练样本数 n
    std::size_t feature_count() const;                  // 特征维数 d
};
```

- **`BruteForce`：已完整实现**（默认）。build = 存一份 X；query = 全量算距离 + `partial_sort` 挑前 k。
- **`KDTreeSearch`：骨架占位**。接口一字不差，`build` / `query` 目前抛 `std::logic_error("not implemented")`——占位就该在 fit 时立刻失败，而不是拖到 predict 才炸。实现它的步骤就照 §4.2：建树时把点按维排序递归切分、query 用「到边界盒距离」剪枝。写完把 KNN 模板实参换掉即生效：

```cpp
KNN<int, float, EuclideanDistance, KDTreeSearch> knn_fast(5);  // fit 目前会抛，实现后即用
```

## 5. k 和投票权重怎么定

**k 是唯一「训练出来的超参数」**（其实是调出来的）：

- **k 太小**（如 1）：对单点噪声极端敏感，决策边界弯弯曲曲、过拟合。
- **k 太大**：把远处的样本也拉进投票，边界过度平滑；若类别不平衡，多数类会长期「霸票」。
- **经验**：从 `k ≈ √n` 起步，用交叉验证在 k = 1,3,5,... 里挑验证集准确率最高的。永远选**奇数** k 是二分类时代的旧习惯（避免平票）；多分类本来就有 tie，靠下面这个规则兜底。

**投票权重**（sklearn 的 `weights` 参数）：
- **uniform（本库已实现）**：每票等权。直觉：只看「哪个类在邻域里人多」。
- **distance**：按距离倒数加权 `1/d`（越近权重越大），能救回「近的一个邻居被远处一群淹没」的尴尬；d=0 时给个无穷大/最大权重特判。

**平票怎么破**（多分类必有）：本库取「并列最多时、标签字典序最小」的那个，保证结果确定可复现（和 `statistics.h` 的 `mode` 同策略）。KNN 平票本质是「邻域里两类证据打平」，真要精细化就去开 distance 权重。

## 6. 和本库代码的对应

### 6.1 用起来什么样

```cpp
#include <mini_mlmath/ml/knn.h>

// 1) 默认：int 标签 + float 特征 + 欧氏距离 + BruteForce
KNN<> knn(3);
knn.fit(X_train, y_train);                // X: n×d；y: n 个离散标签
auto pred = knn.predict(X_test);          // 每行一个多数投票结果
double acc = knn.score(X_test, y_test);   // 分类准确率

// 2) 换 metric（扩展点 A）—— 只改第三个模板实参
KNN<int, float, ManhattanDistance> knn_l1(5);     // 抗噪声用 L1
KNN<int, float, ChebyshevDistance> knn_linf(5);   // 看最大偏差用 L∞

// 3) 看一个查询点到底选中了谁（行号 + 距离，升序）
auto nbrs = knn.kneighbors(X_test);       // [行][邻居]，每个邻居含 .index / .distance
```

标签 `Label` 是泛型的：`KNN<std::string, double>` 也能用（测试里就是 string 标签），只要标签支持 `operator<`（平票排序）和 `==`。

### 6.2 Metric 扩展点怎么自定义

库里的 metric 都是**函数对象（functor）**——一个定义了 `operator()` 的结构体，统一签名「给两个点 + 维数，返回越小越近的标量」：

```cpp
struct MyDistance {                                    // 自定义 metric
    template <typename T>
    T operator()(const T* a, const T* b, std::size_t dim) const {
        T s = T(0);
        for (std::size_t i = 0; i < dim; ++i) s += (a[i] - b[i]) * (a[i] - b[i]);
        return s;                                      // 平方欧氏：省掉 sqrt
    }
};
KNN<int, float, MyDistance> knn(3);                    // 直接换入
```

库里三个 Lp 距离（`EuclideanDistance` / `ManhattanDistance` / `ChebyshevDistance`）本身就是这个签名的示范；§3.3 的余弦 / 汉明 / 马氏想用，照抄这个结构体加进 `knn.h` 即可。**注意签名里只传指针和维数**——这正是为了能直接指向 `Matrix` 某一行（`X.data() + i*X.cols()`），不加容器依赖。

## 7. 局限与扩展

**局限**：
- **predict 慢、吃内存**：懒学习把成本堆在查询端，必须存全部训练数据——这也是向量数据库存在的理由。
- **必须特征缩放**：不标准化，距离被量纲大的特征绑架（§3.4）。
- **高维失效**：距离趋于相等，KDTree 也救不回来（§3.4 / §4.2）。
- **类别不平衡差**：多数类在投票里天然占优；对不平衡数据先考虑加权投票 / 过采样。

**扩展路线**：
- **distance 加权投票**（`weights='distance'`）：补 uniform 的盲区，sklearn 有、本库留作作业。
- **KNeighborsRegressor**：不投票、取 k 近邻标签的**均值**，KNN 就从分类变回归（懒学习的回归版）。
- **KDTreeSearch / BallTreeSearch**：接口已占好位（§4.5），填实现即获得 sub-linear 查询。
- **近似最近邻（ANN）**：工业级超大库用 HNSW / IVF / LSH 等，牺牲一点精确率换百万级召回——那是另一个话题（和 KDTree 同属「邻居索引」族）。
